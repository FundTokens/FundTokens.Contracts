# AGENTS.md

Guidance for AI coding agents working in this repository. Humans: start at
[README.md](README.md).

## What this is

FundTokens: Bitcoin Cash smart contracts (CashScript) for trustless fund tokens backed by
BCH and CashTokens, plus `@fundtokens/builders`, the TypeScript library that builds their
transactions and reads the FundTokens registry. Contracts are organised by **fund type** and
frozen **contract version** (`src/fund-types/<type>/<version>/`).

## Where things are

| Path | Contents |
| --- | --- |
| `fund-tokens-contracts/src/fund-types/<type>/<version>/contracts/*.cash` | Contract sources (`lib/` holds imported functions, not compiled alone) |
| `…/<version>/artifacts/` | Generated by `yarn build:contracts`; never edit by hand |
| `…/<version>/tests/` | Contract, integration, audit and stress tests; `support/` fixtures |
| `…/<version>/*.ts` | That version's builders, encoding, fees, contract derivation |
| `fund-tokens-contracts/src/core/`, `src/registry/`, `src/fund-types/*.ts` | Shared, fund-type independent code |
| `fund-tokens-contracts/test-utils/` | Test helpers and matchers |
| `docs/agents/` | **Implementation-level specs for agents**: every contract rule, transaction layout, byte encoding and limit, per fund type and version |
| `docs/` (other) | Human docs: overview, integration guide, library API, per-version summaries |

Before changing a contract or builder, read that version's
[docs/agents/&lt;type&gt;/&lt;version&gt;/](docs/agents/README.md). The contract source wins over any doc.

## Commands

Run from `fund-tokens-contracts/` (Yarn 4 via Corepack).

| Command | Use |
| --- | --- |
| `yarn build:contracts` | After any `.cash` change (regenerates artifacts) |
| `yarn check:contracts` | Fails if artifacts are stale |
| `yarn bcmr:template` | After changing a BCMR template (`fixed-basket/v1/bcmr.ts`): regenerates the published registry template |
| `yarn typecheck` | Type-checks everything |
| `yarn test` / `npx vitest run <path>` | Tests, skipping the long-running ones in `vitest.config.ts` |
| `yarn test:all` | Every test |
| `yarn verify` | Everything CI runs |
| `yarn metrics` | Contract operation cost estimates |

## Conventions

- **Released versions are frozen.** Change contracts only in an unreleased version; a
  change to a released one ships as a new version directory (see the library README,
  "Adding a fund type version").
- **Line endings.** `.cash` files are CRLF except `startup.cash` (LF); keep each file's
  existing endings. After `git stash pop` or checkout, rerun `yarn build:contracts` if
  artifacts show as stale.
- **Tests that must fail** state why: `toFailRequireWith('<message or statement>')` (debugger,
  cashscript) or `await expect(tx).toBeRejected(/reason/)` (full verification with
  libauth). Passing controls use `not.toFailRequire()` / `toBeAccepted()`. Pair every
  rejection test with an accepted control that differs only in the attacked detail.
- **Random test data.** Use `randomCategory()` and `randomUtxo()` from
  `test-utils/random.ts`; cashscript's own generators have few possible values and collide.
- **Docs.** When behaviour changes, update `docs/agents/<type>/<version>/` (rules, layouts,
  encodings, limits) and, if a reader would notice, the human summary in
  `docs/fund-types/<type>/<version>/`.

## CashScript 0.14 pitfalls

- `&&` and `||` do not short-circuit: both sides run (and both must be valid to evaluate).
- A function must end with a `require`.
- Unused parameters compile to a drop and warn; `padding` parameters are intentionally unused.
- In the cashscript debugger, a final `require(fnCall())` can lose its message, and a frame
  run through `OP_INVOKE` can break location mapping. Put message-bearing checks before the
  final function call, or assert on the failing statement.
- Contract parameters are pushed in reverse declaration order; addresses other contracts
  rebuild depend on that order ([TRANSACTIONS.md](docs/agents/fixed-basket/v1/TRANSACTIONS.md#contract-addresses)).
